# 14 — Glossary

Quick definitions of the recurring terms. For deep dives, the references to the chapters.

| Term | Definition |
|------|------------|
| **Agent** | A system in which an LLM dynamically directs its own steps and tool use in a loop. → [02](02-agenti.md) |
| **Agentic RAG** | RAG in which retrieval is a tool the agent decides when to use. → [05](05-rag.md) |
| **Hallucination** | A fluent but false statement generated by an LLM. → [01](01-fondamenti-llm.md) |
| **A2A** (*Agent-to-Agent*) | A protocol for communication between agents on different runtimes. → [13](13-standard-protocolli.md) |
| **ACI** (*Agent-Computer Interface*) | The interface through which an agent uses tools; to be treated like a UI. → [03](03-strumenti-function-calling.md) |
| **Chunking** | Splitting documents into chunks for RAG indexing. → [05](05-rag.md) |
| **Context engineering** | The discipline of filling the context window with exactly the right information. → [06](06-memoria-contesto.md) |
| **Context window** | The maximum number of tokens manageable in one call; a finite resource. → [01](01-fondamenti-llm.md) |
| **Embedding** | A vector representation of a text's meaning. → [01](01-fondamenti-llm.md), [05](05-rag.md) |
| **Evaluator-optimizer** | Pattern: one LLM generates, another evaluates and gives feedback, iterate. → [07](07-workflow-pattern.md) |
| **Function calling** (*tool use*) | The mechanism by which the model requests a tool's execution. → [03](03-strumenti-function-calling.md) |
| **Gate** | A check (ideally deterministic) between the steps of a workflow. → [09](09-spec-driven-development.md) |
| **Guardrail** | A constraint that limits an agent's behavior regardless of the input. → [12](12-sicurezza-governance.md) |
| **Handoff** | Dynamic transfer of the task to a more appropriate agent (≈ routing). → [08](08-orchestrazione-multi-agente.md) |
| **HITL** (*Human-in-the-loop*) | Human oversight inserted at workflow control points. → [11](11-human-in-the-loop.md) |
| **LLM** | A large language model; predicts the next token. → [01](01-fondamenti-llm.md) |
| **LLM-as-judge** | Using an LLM to evaluate another's outputs. → [10](10-valutazione-osservabilita.md) |
| **Magentic** | Dynamic orchestration driven by a *task ledger* built by a manager. → [08](08-orchestrazione-multi-agente.md) |
| **Maker-checker** | A loop where one agent produces and another verifies against criteria. → [08](08-orchestrazione-multi-agente.md) |
| **MCP** (*Model Context Protocol*) | An open standard for connecting agents to tools/data. → [04](04-mcp.md) |
| **Orchestrator-workers** | An LLM dynamically decomposes the task and delegates to workers. → [07](07-workflow-pattern.md) |
| **Prompt** | The input text to the model (system + user + context). → [01](01-fondamenti-llm.md) |
| **Prompt chaining** | Sequential chaining of LLM calls with gates. → [07](07-workflow-pattern.md) |
| **Prompt injection** | An attack that injects hostile instructions into the data the agent reads. → [12](12-sicurezza-governance.md) |
| **RAG** (*Retrieval-Augmented Generation*) | Grounding generation in an external knowledge base. → [05](05-rag.md) |
| **ReAct** (*Reason + Act*) | A single agent's think→act→observe loop. → [02](02-agenti.md) |
| **Reranking** | Reordering retrieval results by relevance. → [05](05-rag.md) |
| **Routing** | Routing the input to the appropriate specialized process. → [07](07-workflow-pattern.md) |
| **Spec-driven development** | Machine-checkable specifications with deterministic gates. → [09](09-spec-driven-development.md) |
| **System prompt** | Persistent instructions that define role and constraints. → [01](01-fondamenti-llm.md) |
| **Temperature** | A parameter controlling generation randomness. → [01](01-fondamenti-llm.md) |
| **Token** | The unit the model reads/writes with; the basis of cost and latency. → [01](01-fondamenti-llm.md) |
| **Tool** | A function the agent can invoke to observe or act. → [03](03-strumenti-function-calling.md) |
| **Traceability** | The machine-checkable requirement↔task↔test link. → [09](09-spec-driven-development.md) |
| **Vector store** | A database of embeddings for semantic search. → [05](05-rag.md) |
| **Workflow** | A system in which the flow is orchestrated by predefined code. → [02](02-agenti.md), [07](07-workflow-pattern.md) |
